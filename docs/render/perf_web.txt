Browser frame timing of the real valley (warp=M_ZoneA god=1, inside cursed zone A with enemies
on screen), Chrome 157 headless on the RTX 3080 through ANGLE/D3D11, measured with
  tools/render/perf_web.sh --size 1920x1080 --uncapped --settle 22 --hold 8 warp=M_ZoneA god=1 <opts>
"Uncapped" launches Chrome with --disable-gpu-vsync --disable-frame-rate-limit; --settle 22 waits
for the game to be up before timing; raf = requestAnimationFrame over 8 s. GPU timer queries are not
available on web, so chain cost = post=1 minus post=0 (Post's boot option post=0 starts the chain
off). Other workstreams were using the same GPU at the time, so each row was run twice (2026-11-15)
and both runs are listed; the spread between runs is the measurement noise.

1920x1080 uncapped, median ms (p95 ms)       run 1         run 2
  post=0                 (no chain)           4.7 (7.5)     3.9 (5.3)
  post=1 paper=light                          7.4 (10.8)    6.8 (9.0)
  post=1 paper=normal                         7.0 (9.0)     8.4 (12.2)
  post=1 paper=heavy                          7.1 (9.5)     10.0 (13.4)

Chain cost at 1080p on the real valley: Light about 2.8 ms, Normal about 3.4 ms, Heavy about 4.2 ms
(averages of the two runs; single pairs range from 2.3 to 6.1 ms). Whole-frame median stays at or
under 10 ms and p95 at or under 13.4 ms on every preset, inside the 16.7 ms frame at 60 Hz.

Earlier render_demo numbers (first pass) are superseded: paper= did not reach Post in that build
(Settings read it before Boot had parsed the options), so the demo's "heavy" rows measured Normal.
Fixed in 9239620.

The only console error in these runs is the page error "NotAllowedError: A user gesture is required
to request Pointer Lock." from gameplay's mouse capture in a headless page without input.
